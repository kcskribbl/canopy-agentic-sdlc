# Key-bound local approvals

For a supervised workspace, enroll an operator-trusted **public** OpenSSH Ed25519 key before starting any runs. The reviewer keeps the private key; do not copy it into Canopy. Enrollment is trust-on-first-use, not enterprise identity verification.

```powershell
$ws = '.canopy\signed-review'
python engineering\control.py --workspace $ws enroll-reviewer release-owner C:\keys\reviewer.pub
python engineering\control.py --workspace $ws run trial scenarios\greenfield\scenario.json
python engineering\control.py --workspace $ws inspect trial requirements
$reason = 'Acceptance criteria match the reviewed scope.'
python engineering\control.py --workspace $ws challenge trial approve $reason decision.json
Get-Content decision.json
```

Only if you agree with the exact bytes shown, sign on the reviewer machine using OpenSSH 8.2+:

```powershell
ssh-keygen -Y sign -f C:\keys\reviewer -n canopy-local-review-v1 decision.json
$s = python engineering\control.py --workspace $ws status trial | Out-String | ConvertFrom-Json
python engineering\control.py --workspace $ws approve trial $s.digest $reason --signature decision.json.sig
python engineering\control.py --workspace $ws resume trial
```

Use a fresh filename and decision for each gate (`reject` works the same way). Signed scopes include the workspace nonce, run, revision, gate, digest, decision, rationale and enrolled principal. An unsigned interactive or policy-file decision cannot bypass the signature requirement in an enrolled workspace. The raw decision and signature are retained as a content-addressed artifact.

**Boundary:** this authenticates possession of the enrolled signing key at the four approval gates. It does not authenticate every local command, identify a person independently, prevent local DB administration, support key revocation, or sandbox Maven code. Unsigned workspaces and fixture replays remain explicitly local demonstrations. Test keys generated by the regression suite are ephemeral and never represent a human release.
